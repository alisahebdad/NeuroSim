# DNN+NeuroSim V1.5 + GPT-2 port — pip requirements
# Derived from upstream conda `environment.yml` (see report.md §1.5).
#
#   python -m venv .venv && source .venv/bin/activate
#   pip install --upgrade pip
#   pip install -r requirements.txt
#   pip install -e pytorch-quantization      # REQUIRES nvcc — see note below
#
# ── WHY THESE ARE FLOORS, NOT PINS ───────────────────────────────────────────
# environment.yml pins a late-2023 stack (torch 2.1.1, python 3.11.5). That
# stack is UNREACHABLE on Python 3.12+: torch 2.1.1 publishes no wheels for it,
# and pip fails with "no matching distribution". Both development machines here
# run Python 3.14.
#
# Rather than pin versions that cannot be installed, this file specifies
# floors and lets pip resolve. The trade-off is explicit: results are NOT
# bit-comparable to published NeuroSim numbers produced on the original stack.
# Reproducibility comes instead from a lockfile — after a successful run:
#
#     pip freeze > requirements-lock.txt
#
# and commit it. A lockfile of a stack that works beats a pin of one that
# cannot be installed.
#
# To reproduce upstream exactly instead, install Python 3.11 and pin
# torch==2.1.1, torchvision==0.16.1, numpy==1.26.2, scipy==1.11.4,
# transformers==4.35.2 (the versions named in environment.yml).
#
# ── HARD REQUIREMENT: NVIDIA GPU + CUDA toolkit ──────────────────────────────
# `pytorch-quantization/setup.py` builds a CUDAExtension from
# `src/tensor_quant_gpu.cu`, and `tensor_quant.py:28` imports it
# unconditionally with no CPU fallback. The package cannot be built or even
# imported without CUDA. See report.md §1.6.
#
# ── TORCH: DO NOT LET PIP REPLACE A WORKING BUILD ────────────────────────────
# The floor below is satisfied by any already-installed torch >= 2.9, so
# `pip install -r` will leave an existing install untouched. If you install
# torch fresh and need a specific CUDA version, install it FIRST from
# https://download.pytorch.org/whl/<cuXXX>, then run this file.
